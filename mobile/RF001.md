# RF-001: registro ciudadano móvil

La ruta inicial `/` de Expo Router presenta UIM-01 con nombre, correo,
contraseña y confirmación. Solo se envían nombre, correo y contraseña a
`POST /api/v1/ciudadanos` de la API central. El éxito no inicia sesión
(RF-002 no forma parte de esta entrega).

Copia `.env.example` a `.env.local` y configura `EXPO_PUBLIC_API_URL` con
el origen HTTPS de la API, sin `/api/v1/ciudadanos`. El valor es público:
no incluyas credenciales, claves de Supabase ni conexiones PostgreSQL.
En desarrollo se permite HTTP únicamente en localhost, 127.0.0.1,
[::1] o 10.0.2.2 (host desde emulador Android). Un dispositivo físico
requiere un origen HTTPS alcanzable; localhost apunta al propio dispositivo.

El formulario conserva datos tras fallos, impide envíos simultáneos y
elimina contraseñas tras la confirmación. Un timeout de 15 segundos no
prueba que la transacción haya fallado: se advierte de esa incertidumbre.
Los errores 409, 422, 503 y de red se muestran en español. No se muestran
respuestas arbitrarias del servidor ni se almacenan contraseñas.

Comandos desde `mobile/`:

- `npm ci`
- `npm run lint`
- `npx tsc --noEmit`
- `node --test tests/registration.test.mjs` (Node 24, sin dependencias)
- `npx expo start`

La revisión estática confirma etiquetas persistentes, errores textuales
incluidos en la etiqueta accesible, anuncios de error/éxito, foco en el
primer campo inválido, controles táctiles de al menos 44 puntos y desplazamiento
para teclado. Esta revisión no certifica WCAG ni sustituye pruebas con
TalkBack/VoiceOver y dispositivos reales. La navegación usa un Stack de
Expo Router; la confirmación permite volver al formulario de registro.

## Ajuste visual UIM-01 · 2026-11-07

Referencia local: `ref/SGIP-Mockups.html`, registro de UIM-01. Se usan los
colores bosque #173d35, verde #17634e, lima #d8ec91, fondo #f3f5f0 y
estados textuales. Marca con señal de avance, tipografía del sistema nativo,
etiquetas persistentes, espaciado y bordes del HTML adaptados a React Native.
El formulario no incluye marco de teléfono, selector ni navegación de demostración.

Diferencias para decidir alcance: el mockup separa Nombres y Apellidos y añade
Teléfono; se conserva Nombre completo del contrato RF-001 y se omite Teléfono.
El mínimo de ocho caracteres del mockup se mantiene en doce según el contrato
vigente (máximo 128, sin recortar espacios). Ingresar y las rutas posteriores
corresponden a otros RF; se presenta solo el modo Crear cuenta. La advertencia de
demostración no aplica al cliente integrado. Confirmación sigue siendo local.

Se añade Mostrar/Ocultar contraseña con etiqueta accesible y se oculta de nuevo
tras el éxito. Se conservan el servicio, payload, validaciones, foco en el primer
error, anuncios accesibles, bloqueo de doble envío y datos tras fallos.
KeyboardAvoidingView ajusta iOS con padding y Android con height; ScrollView
permite desplazamiento y descarta teclado al arrastrar. El teclado de correo,
autocompletado y las acciones Siguiente/Hecho mantienen el orden del formulario.
Foco ámbar, error rojo con texto, carga deshabilitada y confirmación verde.

Verificación actual: revisión estática de componentes y contrato completada;
Android/iOS, teclado real, TalkBack y VoiceOver pendientes: no se usó dispositivo
ni emulador. Los resultados de comandos actuales se registran abajo al finalizar.

Revisión incremental de frontend_movil: se preservó el rediseño local existente
tras comparar el diff completo de mobile con HEAD y con el HTML. Al recibir el
éxito de la API se descarta el teclado nativo y la confirmación aclara, también
en el anuncio accesible, que no se ha iniciado sesión. No cambian servicio,
payload, validaciones ni conservación de datos tras errores.
